# 自有整合镜像：构建与发布前置条件

这是维护者路线图，不是一键打包承诺。当前分支已提供源码和部署说明，**没有产出或实测新的整合镜像**。给另一台同型号机器使用，优先走[基础镜像加定制部署](new-device-guide.md)。本次文档工作不授权采集现有设备、停止其服务、发布镜像或刷写另一台机器。

## 1. 为什么不能直接导出当前机器发给别人

当前机器有模型/后台凭据、Wi-Fi、SSH授权、聊天/浏览器/媒体数据；完整系统读回不是可公开发布的通用镜像。`image/pull-from-device.sh` 也只做捕获，**不脱敏**；它会短暂停止客户端和网关，输出仍含个人数据。不要上传捕获 tar、旧设备 system 镜像、原厂整盘或注入网络的私有 bootstrap。

现有 `image/sanitize-rootfs.sh` / `image/build-image.sh` 是上游的出镜像基础，不是本 fork 已做完的整合构建流水线。必须先审查以下缺口：

| 事项 | 当前脚本行为与待完成工作 |
| --- | --- |
| 网关补丁 | 构建要求网关工作树干净，提交位于发布分支；设备上未提交的补丁会使检查失败。必须在独立维护的网关仓库纳入改动并确定更新策略，不能靠关闭检查 |
| 网关来源 | build-image.sh 仍会把镜像内网关 origin 重写为 justhalfbit/xiaozhi-hub-server。若发布自己的网关提交，须先设计并审查相应来源/分支处理，不能仅改 HUB_MAIN 就以为全部解决 |
| 网关默认配置 | 脱敏会从指定提交的 config.template.yaml 重建 data/，因此设备私有配置里的模型、工具、默认城市不会自然成为发布默认值；需无凭据模板或首启设置流程 |
| 洛雪配置 | 脱敏清掉用户 .config 下的应用配置，启动全屏和音源选择也会消失；需首启重新初始化/说明，不从私有配置直接复制 |
| 用户入口 | 脱敏清掉 .local/share，其中包含本用户媒体 desktop 入口；若要随镜像提供，需重新生成通用入口并实测 |
| 账号/SSH | 脚本会移除 authorized_keys/主机密钥，但不自动重建适合发行版的账户锁定和 SSH 策略。直接捕获“账户已锁、公钥专用”的设备会造成新机失去 SSH 管理入口；需独立设计首启安全配置，不能内置维护者公钥或恢复共享弱密码解决 |
| 私人辅助文件 | home 清理不能代替逐一审查 /usr/local、/etc、systemd 环境和其它位置里的私有脚本、代理、令牌、备份、source JS及媒体缓存 |
| 容量/依赖 | 装入两个 Electron 客户端会增大镜像和首启占用，须核对 system 分区、根文件系统、inode和实际剩余空间，不能只按基础镜像大小估算 |

这些只是明确的发布阻断项，不代表完成它们就无需整体安全/功能检查。当前不发布未经解决和验证的整合 `.img`。

## 2. 可复现构建需要记录什么

- 本 fork 的准确提交、基础镜像/内核/DTB/codec/Mesa版本和校验、关键 held 包清单。
- 客户端代码/依赖版本、独立网关仓库 URL/提交/发布分支、补丁及配置模板版本。
- 媒体 ARM64 包来源、版本、校验、依赖；音乐源默认不嵌入，更不打包个人授权。
- 从干净基础准备构建参考机或隔离 rootfs；不直接以日常有账号/密码锁定策略的设备作为“已清理模板”。
- Linux/macOS 构建主机和可运行项目 Dockerfile 的 Docker环境；磁盘、内存以及固定 Docker卷 `tsimg-work` 的占用。脚本会重建该卷内工作目录，不与其它构建任务共用同一工作卷。

`image/device-setup.sh` 含设备服务安装、桌面移除、驱动/DTB等不同动作，不能整段无审查执行；codec涉及写启动分区，必须单独核验授权。现有正常运行设备不为制镜像而盲目重跑全部 setup。

## 3. 现有工具的接口及边界

下列仅展示接口占位，**不是当前可直接发布的步骤**。所有路径必须是事先核对的绝对路径、位于仓库外的专用私有目录，不能是已有原厂备份路径。

1. 捕获：`TS_HOST=<参考机当前IP> bash image/pull-from-device.sh <私有捕获目录>`。需准备 ts.sh 指定的专用 SSH key/known_hosts，并对参考机暂停服务取得同意；输出 boot.tar.zst、root.tar.zst、versions.txt，均按敏感资料保管。
2. 脱敏/构建：`bash image/build-image.sh <私有捕获目录> <候选输出目录> <网关源码目录> <私有敏感字符串清单>`。脚本使用 Docker 在副本清理、做文件系统/内容检查、压缩、输出校验及包清单；只在第1节阻断项解决后评估执行。
3. 敏感字符串清单逐行由维护者本机提供，涵盖Wi-Fi、个人地址/设备标识、API/GitHub令牌、代理等，不写入公开仓库；脚本会复制到捕获目录，也应一并保护。模式扫描只是辅助，扫描通过不证明所有隐私均已剔除。
4. 产物应包含 `.img.xz`、两种形态的 SHA256SUMS、packages.txt、image-info.txt和可追溯源码/依赖信息。构建成功不等于能启动，更不等于已获准公开。

不要直接复制文档中的占位接口运行，更不能为了通过检查跳过“网关在发布分支且工作树干净”、文件系统或隐私门槛。

## 4. 发布前必须完成的实物验收

在**另一台有独立合格原厂备份的同型号试验机**上，经该机所有者逐项同意后执行刷写。至少完成首次开机、无预存Wi-Fi的配网、生成独立主机密钥/身份、安全管理员入口、根分区扩展、导航/语音/工具、媒体首次初始化及可控更新/回退。

确认没有参考机的账号、密码、公钥、SSID、代理、聊天、cookie、设备ID或音乐源；换网络并重启后重新验收。记录失败和限制，至少覆盖文档中的[设备检查表](device-checklist.md)，不能把原机器测试结果当新镜像实测。

只有上述阻断项和测试完成、维护者明确同意发布，才在自己的 fork 创建**新的明确标签和 Release**，上传已检查的通用产物、校验、发行说明和对应源码归属。不要覆盖上游资产，不上传私有捕获，不把当前源码分支/旧上游 Release 伪称成已包含全部定制的镜像。
