# 定制设备的维护、故障判断与回退

适用范围和安装顺序见[新设备部署指南](new-device-guide.md)。以下是检查/处置说明，不授权远程自动操作其它设备。

## 1. 每台设备保留哪些记录

在仓库外保留该机独立原厂全盘备份、GPT、校验及刷写日志；另保存基础镜像版本、fork 提交、网关提交、客户端版本、媒体包版本、已应用补丁、测试结果。备份至少跨盘两份，私有目录 700、敏感文件 600；不要把文件名中夹带令牌。

更新前备份本机的网关 data/（含聊天数据库、密钥和后台配置）、客户端设置、Wi-Fi 配置，以及要改的源码/包装器。备份活动数据库要按[原教程的数据备份步骤](../README.md#41-刷机前备份)暂停相关写入并确保重新启动。整包恢复仅用于**原设备**，不是跨机器模板。

## 2. 四种更新不能混用

| 对象 | 当前来源/处理 | 风险和验收 |
| --- | --- | --- |
| 语音客户端 | 原镜像的独立客户端更新渠道 | 本 fork 的分支推送不会自动成为客户端更新；升级后检验 UI 元素、唤醒和返回主页 |
| 小智网关 | 独立的 xiaozhi-hub-server 仓库 | 本地天气/TTS补丁可能使更新停止或被新代码覆盖；先留差异、在副本重放测试，不 `reset --hard` |
| 浏览器/启动器 | 此 fork 的明确提交，按新设备指南备份并安装 | 只重开必要进程，不为两文件更新重跑 purge/tidy/codec |
| 系统包/内核 | 原镜像测试过的固定版本 | 不把解除 hold、整机 apt upgrade 或换内核作为日常优化；安全更新需独立评估兼容性 |

发布维护者的 GitHub 令牌不放到终端；公开读取源码不需要它。不要只把 `/etc/thinksmart-update.conf` 指向本镜像仓库：它需要的是特定客户端更新清单/安装包，而非刷机 `.img`。相关发布格式见 [update/README.md](../update/README.md)。当前更新没有独立签名，HTTPS/校验不等于来源永远可信。

## 3. 先分清故障在哪一层

| 现象 | 优先检查 | 不应直接得出的结论 |
| --- | --- | --- |
| 没有唤醒回应 | 实体隐私开关、麦克风输入、PipeWire/虚拟源、唤醒事件 | audio=true 不证明输入回调正在收到声音 |
| 能唤醒，无识别文字 | 实际输入、识别/网关连接、换网后的路由/代理 | 不先怪大模型音色或内存 |
| 有识别文字，无回答文字 | 模型配置/鉴权/额度/超时/工具调用链 | Wi-Fi 连上不代表每个云 API 都通 |
| 有回答文字，无声音 | 所选 TTS、Edge直连/可选代理、超时、输出设备 | 硅基流动模型正常不代表 Edge TTS 正常 |
| 能聊天，天气/新闻失败 | 工具是否启用且实际调用、对应服务可达性 | 模型自述“不联网”不是设备网络检测结果 |
| 排行榜正常，歌曲不播 | 当前选中源、歌曲平台/音质、播放地址、实际输出 | 列表和进程存在不是出声验收 |
| 黑屏/按钮迟钝 | 应用窗口、重复实例、实际内存/CPU/GPU现场 | 不能只凭2GB内存认定耗尽，也不直接重刷 |

设备 ubuntu SSH 会话中的低风险检查：

```sh
systemctl is-active thinksmart-kiosk thinksmart-client
systemctl --user is-active pipewire wireplumber thinksmart-mic xiaozhi-hub
curl --max-time 5 -fsS http://127.0.0.1:8090/api/health
wpctl status
free -m
df -h /
ip -4 -br addr show wlan0
```

不要全量打印私有配置、后台快照或聊天日志。排错日志先本机限时/筛选，公开前脱敏。测试录音需另征得同意；一般先用 PipeWire 在内存统计，不保存/上传原始录音。**不直接打开 ALSA 硬件 PCM**（speaker-test/aplay 的 hw 设备等），本机音频 DSP 可能因此卡死。

### 换 Wi-Fi 后语音失败

确认设备的新 IP，电脑连同一网络；检查手机热点隔离/门户认证、DNS、时间同步及外网访问。模型、TTS、天气、新闻分别诊断。不把旧家庭代理或虚拟机地址保留为必需，HTTPS 校验失败时不关闭证书校验来“修复”。遇到网页验证码由用户手动完成，不绕过。

### 音频服务正常但没有输入

只读查看源和事件，不绕过实体静音开关。若确认 DSP/采集异常，先记录首次错误和重启计数，再经用户同意做一次正常重启，重验真实唤醒和出声；不是 health=true 就宣称修复。反复重启不能替代根因分析。

## 4. 按层回退，不动原厂校准

### 浏览器/导航

关闭媒体窗口，核对新设备指南中记录的备份目录。先恢复备份的主程序；若备份也有导航模块，再一并恢复。模块原本不存在时，确认没有其它使用者后可以移除本次新增模块，也可以暂留不再被导入的模块，不删除其它 `/usr/local/bin` 文件。核验权限并只重开浏览器。不要恢复另一台设备的 `/etc` 或用户目录。

### 媒体启动器和应用

`media/install-launchers.sh` 的旧启动器/desktop 入口在其输出的 `/var/backups/thinksmart-media.*` 中，逐文件核对后恢复；原本没有的入口只能在确认是本次新建时移除。

需要卸载媒体时，先正常关闭，再对确切包使用 `apt-get remove`，例如 `lx-music-desktop` 或 `io.github.msojocs.bilibili`。先模拟并取得所有者同意；不 `purge`/`autoremove`，不清 cookie、账号、曲库/播放列表。重开浏览器后相应按钮隐藏。保留已校验安装包和私有配置备份以便恢复。

洛雪全屏工具只改一字段，其备份在本机 `~/.config/lx-music-desktop/LxDatas/config-before-fullscreen-*.json`。如仅想改全屏，优先在关闭应用后只改该字段；整份恢复会覆盖后来新增的其它设置，必须先比较。

### 可选网关补丁

必须使用与部署时相同的补丁并先保存本机配置。对目标源码确认没有后续用户改动，先只读检查反向应用：

```sh
# 在保存了对应版本补丁的 fork 根目录执行；只读检查，不等于已经回退：
git -C /home/ubuntu/xiaozhi-hub-server apply --reverse --check "$PWD/extras/hub/voice-weather.patch"
```

检查通过且所有者确认后，停止网关，再用相同命令去掉 `--check` 执行反向应用。把私有配置中的天气 provider/工具策略等回退成与旧代码兼容的值；源码反向应用不自动还原配置。然后启动网关、验证基础问答和声音。任何上下文不符或已有新修改都停止，不能强制丢弃工作树。已有其它文件引用新天气模块时也不能删它。

### Linux 系统或原厂系统

重刷 system 会清除当前 Linux 数据，按原教程路线 B，先做本机备份；不重新改 GPT。恢复原厂涉及整盘写回，只能用**这台机器自己的**合格原厂备份，目标/备份/校验重新核对并取得单独明确同意，不能把常规回退升级成整盘写入。没有自己的原厂备份就不能宣称可无损恢复原厂。

紧急模式、boot I/O 错误、异常分区不要套用另一台机器的扇区数字。先读回留底，再按[原教程故障章节](../README.md#3-常见问题排查)核对；保留未知/失败现场，别连续写盘。

## 5. 安全停机与长期使用

Ubuntu 使用屏幕关机或 `sudo systemctl halt`，黑屏后至少10秒再拔电，断电约30秒后接回。不把直接拔电作为退出媒体的方式。无电池、8GB eMMC、2GB内存意味着需要控制日志/缓存和应用数量；不能承诺任意视频站流畅或永不需要维护。

每次换网络、升级组件或更换音源后，重做对应的[验收表](device-checklist.md)，未测试项明确标“未验证”，不能沿用旧网络或另一台机器的成功结果。
